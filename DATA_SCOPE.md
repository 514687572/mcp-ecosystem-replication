# Data scope of the public package

## Included

- The full pipeline: harvest, census analysis, package enrichment, tool
  extraction, GitHub enrichment, cross-source analysis, human-coding ingestion,
  inter-rater statistics and packaging.
- The 30 result tables reported in the manuscript, each regenerated by a named
  script step.
- The human validation material: the three coding worksheets as issued, the
  coded results returned, the evidence packs, the reliability statistics, and
  the disagreements in full.
- The seeded sample records (`data/interim/tool_sample.json`,
  `data/interim/registry_cursor.json`).
- All three codebook versions, so the revision history the manuscript describes
  can be checked against the artefacts.
- The manuscript source and the tooling that checks its format, citations and
  style metrics.

## Excluded

**The raw registry harvest.** At 131 MB it is the single largest artefact, and
the upstream registry is its authoritative copy. Redistributing a snapshot
would create a second copy that silently diverges as the registry grows. The
manifest records the digest of the snapshot used, which is what "verify our
snapshot" actually requires.

**The HTTP cache.** A performance artefact, regenerable from public sources.

**Credentials.** The pipeline reads a GitHub token from a gitignored `.env`
file, or from the environment. No credential is present in this package, and
the GitHub steps are optional: they need a read-only token only to raise the
rate limit from 60 to 5,000 requests per hour.

## Collection ethics

The study collects only published artefacts. It does not call MCP server
endpoints, does not attempt authentication against them, and does not execute
any server code. Package sources are downloaded and parsed as text; the tool
extraction step never imports or runs what it reads. Repository metadata comes
from the GitHub API under a read-only token.

The human coding pass judged servers and tools from published artefacts only.
Its codebook states explicitly that coders must not probe live endpoints.

## Reproducing the production aggregates

Steps 1–7 need network access and rebuild every input:

```
python scripts/01_harvest_registry.py     # resumable; ~1,150 pages
python scripts/02_analyze_registry.py
python scripts/03_enrich_packages.py --workers 8
python scripts/04_extract_tools.py --sample 1200 --seed 20260924
python scripts/05_enrich_github.py --releases --sample 800 --seed 20260927
python scripts/06_cross_analysis.py
```

Steps 8–18 are offline:

```
python scripts/08_validate_extraction.py --sample 150 --seed 20260925
python scripts/09_make_coding_sheets.py
python scripts/10_ingest_part_a.py --codes results/validation/T1.txt
python scripts/11_ingest_part_b.py
python scripts/12_ingest_part_c.py
python scripts/13_interrater.py
python scripts/15_make_interrater_pack_v12.py
python scripts/16_version_vs_release.py
python scripts/17_build_facts.py
```

## A note on the network environment

On the machine that produced this package, GitHub was reachable only through a
local proxy that failed intermittently, and the proxy also intercepted every
other host. `config/config.yaml` therefore exposes `http.proxy_mode`
(`auto`, `none`, or a fixed URL), and `scripts/05_enrich_github.py` accepts
`--proxy none`. This affects fetch time only, never a reported result.
